# Контекст ревью: локальный форк vs апстрим

Репозиторий `/Users/vladislav.molchanov/Desktop/Projects_downloaded/claude-viewr-competitors/agentsview` —
форк `kenn-io/agentsview` (remote `upstream`). Пользователь ведёт локальную ветку `main`
с 129 коммитами поверх апстрима и периодически мержит апстрим.

- `7fb07fd7e33f055960dd680d5d3c049a6b2cb9b2` (далее BASE) — merge-base, состояние
  апстрима на момент последнего мержа. Вся история апстрима до BASE включена в main.
- После BASE в `upstream/main` пришло ещё 20 коммитов (список —
  `scratch/review/meta/upstream-commits.txt`). Они в локальный main НЕ вмержены.
- Локальная дельта: ~22k строк в 220 файлах (список —
  `scratch/review/meta/local-files.txt`, коммиты — `meta/local-commits.txt`).

## Артефакты для сравнения

В `scratch/review/`:

- `scratch/review/_base/<путь>` — содержимое файла на момент BASE (апстрим-версия
  до локальных правок). Если файла нет в `_base` — он новый, локальный.
- `scratch/review/<группа>/files.txt` — файлы группы.
- `scratch/review/<группа>/local.patch` — дифф BASE→main по файлам группы.
- `scratch/review/<группа>/upstream.patch` — дифф BASE→upstream/main по тем файлам
  группы, которые апстрим тоже трогал после BASE (есть не у всех групп).
- Текущие версии файлов читаются прямо в рабочем дереве.

## Задача ревьюера

Оценить, не стали ли локальные правки ХУЖЕ апстрим-версии. Искать:

1. **Потерянное поведение** — локальный дифф удаляет или ослабляет логику,
   которая была в BASE (проверки, обработку граничных случаев, fallback'и,
   очистку ресурсов, валидацию), не заменяя её эквивалентной.
2. **Регрессии исправлений** — в BASE был багфикс, а локальный код его
   откатывает или обходит.
3. **Ослабленные тесты** — удалённые/ослабленные утверждения, скипнутые тесты,
   потерянное покрытие того, что было покрыто в BASE.
4. **Параллельные решения** — если upstream.patch существует: апстрим после BASE
   решил ту же проблему иначе. Оценить, чья версия корректнее/полнее и
   насколько болезненным будет следующий мерж.
5. **Новые баги** — в локальном коде: гонки, утечки, незакрытые ресурсы,
   нарушение инвариантов, которые гарантировал BASE.

НЕ отмечать как проблему: отличия ради новой функциональности, рефакторинг с
сохранением поведения, стилистику, отсутствие в локальной ветке апстрим-коммитов,
не связанных с файлами группы (это просто ещё не вмержено).

## Формат ответа

Для каждой находки: `SEVERITY | файл:строки | суть | что было в BASE/апстриме`.
Severities: `WORSE` (локаль явно хуже — потеря корректности/поведения),
`RISK` (вероятная деградация или болезненный мерж), `NOTE` (наблюдение, не
деградация). В конце — вердикт: чисто / есть проблемы, и числовая сводка.
